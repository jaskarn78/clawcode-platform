# Memory system overhaul plan (2026-10-25)

Companion to `audit-2026-10-25.md`. Goal: give every agent the most useful context at boot and per turn, and make everything the agent was told, saved, or was sent as a file or image reachable later, by fixing the pipeline that exists rather than replacing it.

Other facts: dream passes fire 50 to 80 times a day per idle agent (9,077 applied runs, graph-edges.json up to 680 KB); no agent has a context-summary.md; access_count never reaches 3 (hot promotion happens only through auto:similar centrality, which the flush rows dominate); state-contract has 13,458 document chunks but only 665 reached the memory mirror; three agents keep their memory dir at memory/memory; the dedup threshold (0.85) is applied against all 10,000 plus flush rows on every insert.

## Principles adopted from the research

1. Keep verbatim turns and raw files indexed; summaries and extracted facts are pointers, not replacements.
2. Fine-grained retrieval units (a few hundred words) with contextual headers (source, date, page) written into the indexed text.
3. BM25 and vectors as independent candidate channels, fused by rank; path and type priors sized to the fused score scale; recency as a bounded tie-breaker, never a hard cutoff.
4. Explicit supersession with dates instead of destructive merges; forgetting by archiving and ranking, not deletion.
5. Small, curated, dated always-loaded core; everything else on demand through tools that return references with provenance.
6. Capture, flush and consolidation off the hot path, novelty-gated, non-destructive and idempotent.
7. A recall regression suite with planted facts, run in CI.

## Work packages

Each package is owned by one implementer in its own worktree. File ownership is exclusive inside `session-manager.ts`, `store.ts` and `daemon.ts` by line region so the branches merge cleanly.

### WP1 Flush flood, hot tier and cleanup
Files: `src/memory/session-summarizer.ts`, `src/memory/tier-manager.ts`, `src/memory/tiers.ts`, `src/memory/similarity.ts`, `src/memory/store.ts` (promotion and cold candidate SQL at 1395 to 1489 only), `src/manager/session-manager.ts` (startFlushTimer and flushSessionIfPossible region, 3969 to 4020 only), new `src/cli/commands/memory-prune-flush.ts` plus its registration in `src/cli/index.ts`.
- Mid-session flush summarizes only turns added since the previous flush, skips when fewer than 4 new turns, stores at importance 0.4, and the final session summary deletes that session's mid-session rows (the summary supersedes them).
- Session summarizer keeps the head and the tail of each turn when truncating, so conclusions survive.
- Auto-linking (similarity.ts) skips rows tagged mid-session, session-summary and raw-fallback; hot promotion and centrality exclude those tags; getHotMemories never returns them.
- One-shot operator cleanup `clawcode memory prune-flush <agent> [--apply]`: dry-run by default; deletes mid-session rows whose session already has a summary, then re-runs tier maintenance. Never automatic.

### WP2 Retrieval ranking, query hygiene, provenance
Files: `src/memory/memory-retrieval.ts`, `src/memory/memory-chunks.ts`, `src/memory/fts-query.ts`, `src/memory/embedder.ts`, `src/memory/embedder-bge-small.ts`, `src/manager/memory-context-augmenter.ts`, `src/manager/recall-footer.ts`, `src/manager/session-manager.ts` (getMemoryRetrieverForAgent region, 839 to 948 only), `src/memory/eval/*` and new tests.
- Strip the Discord `<channel ...>` envelope from the retrieval query and the cadence-gate cosine (shared helper exported for WP4 to reuse on the stored turn).
- Path and document weights become multiplicative on the fused score (score times 1 plus weight), so they nudge within the RRF range.
- Over-fetch 60 candidates per ranker; replace the hard 14-day drop with a soft recency multiplier for dated chunks (floor 0.35), standing paths untouched; apply tag exclusion before ranking.
- Long H2 sections are split into sub-chunks of about 220 words with a part suffix; bge-small embeds up to 350 words.
- Embedding failure no longer discards keyword recall: run FTS alone and log once.
- Budget loop skips an oversize chunk and keeps filling instead of breaking.
- Every rendered hit carries a date and source kind in its heading; createdAt reaches the output and the recall footer.
- Document chunk cap per turn rises from 2 to 4.
- Recall regression suite: planted facts, envelope-wrapped queries, competing vault and document chunks, a flood of flush rows, old notes; asserted floors.

### WP3 Documents and uploads
Files: `src/document-ingest/*`, `src/documents/*`, `src/manager/auto-ingest-handler.ts`, `src/manager/auto-ingest-queue.ts`, `src/heartbeat/checks/auto-ingest-rescan.ts`, `src/heartbeat/checks/attachment-cleanup.ts`, `src/manager/daemon.ts` (delete-document and search-documents cases, and the tool-cache registration near 7054 only), `src/mcp/server.ts` (search_documents and ingest_document descriptions only).
- Contextual header on every chunk before embedding and FTS: filename, upload date, sender and channel when known, page and chunk index; memory mirror heading is the filename, never null.
- Cross-ingest re-chunks to about 300 words; a document whose mirror is missing is re-mirrored by the rescan.
- search_documents applies the source filter before KNN; its cache is invalidated on ingest, delete and priority change.
- delete_document removes the provenance row and the memory mirror.
- No raw binary bytes are ever chunked; with no text and no caption the handler stores a one-line stub and schedules a retry.
- Tesseract confidence comes from the tsv word confidences; mixed PDFs OCR the pages that have no text layer.
- The attachment cleanup check sweeps the real inbox directory.

### WP4 Capture and continuity
Files: `src/discord/capture.ts`, `src/memory/conversation-store.ts`, `src/memory/conversation-brief.ts`, `src/memory/memory-flush.ts`, `src/memory/memory-scanner.ts`, `src/manager/session-manager.ts` (startMemoryFileFlushTimer, stopAgent and reconcileRegistry regions only), `src/manager/daemon.ts` (scanner start region near 5467 to 5541 only), `src/manager/session-memory.ts` (saveContextSummary only).
- Stored user turns hold the user's words, not the envelope.
- listRecentTerminatedSessions includes sessions whose turns were pruned after summarization.
- The Recent Sessions brief is injected on every fresh session (no 4-hour skip), bounded by its token budget.
- The disk flush does not advance its cursor on an aborted or empty summary (bounded retries, then a raw fallback); the flush timer starts on the resume path too.
- The scanner backfills on start and is recreated on per-agent restart.
- At session end the final summary is written to context-summary.md with a timestamp so boot has a real resume summary.

### WP5 Storage integrity, supersession and tools
Files: `src/memory/dedup.ts`, `src/memory/store.ts` (schema migration, insert and search statements; not the tier SQL), `src/manager/session-memory.ts` (MemoryStore construction only), `src/memory/consolidation.ts` (skipDedup on digest inserts only), `src/memory/tools/*`, `src/mcp/server.ts` (memory tool registrations), `src/manager/daemon.ts` (memory tool IPC cases near 18529 to 18755 only), `src/manager/capability-manifest.ts`.
- New columns superseded_by and superseded_at; retrieval and search exclude superseded rows by default.
- Dedup never overwrites: at cosine 0.95 or above the new row is dropped as a true duplicate (returning the existing id); between the threshold and 0.95 the new row is inserted and marked as superseding the old one. The config knob is wired.
- memory_save returns what happened (created, duplicate, superseded). New tools clawcode_memory_forget and clawcode_memory_update; recall accepts shared ids; search results carry created date, source kind and path.
- The memory protocol in the manifest is always present, names clawcode_memory_search and search_documents, and tells the agent to save durable facts with absolute dates.

### WP6 Injection
Files: `src/manager/session-config.ts`, `src/manager/context-assembler.ts`, `src/memory/context-summary.ts`.
- System prompt directives are rendered into the stable prefix from the resolved config.
- USER.md gets its own budget and is truncated last; the truncation marker is kept.
- Hot memories render with dates; the resume summary ignores placeholder text and anything older than 7 days.

### WP7 Dreaming and consolidation
Files: `src/manager/dream-*.ts`, `src/manager/idle-window-detector.ts`, `src/memory/consolidation.ts` (everything except the skipDedup line), `src/memory/memory-cue.ts`, `src/cli/commands/dream.ts`.
- A dream pass records when it ran and skips when nothing new was written since.
- dream.model is honored; graph-edges.json is capped and deduplicated.
- The themed reflection is written under memory/digests so it is indexed as standing memory.
- Consolidation handles a past week with fewer than threshold logs once the week is over, truncates head and tail, and inserts digests with skipDedup.
- The cue regex no longer fires on recall questions.
